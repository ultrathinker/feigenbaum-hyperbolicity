## `03-CERTIFICATES/existence/` — 46 боксов существования

Файл `box_<тег>.json` на каждый бокс. Тег `g00…g43` — регулярная сетка
`ℓ₀ = 2.025 + 0.045k`, `ganchor` — бокс с центром `ℓ₀ = 3`, `gtop` —
верхний, `ℓ₀ = 3.9925`.

| поле | смысл |
|---|---|
| `ell0`, `w`, `ell_lo`, `ell_hi` | центр, ширина и границы `ℓ`-бокса |
| `m`, `D`, `prec` | степень чебышёвского центра, степень σ-модели, точность arb |
| `Y0` | `sup_ℓ ‖Ã F̃(P(ℓ), ℓ)‖` по боксу (голова + хвосты) |
| `Z1`, `Z1b`, `Z1c` | `sup_ℓ ‖I − Ã M′(ℓ)‖₁` и его хвостовые части |
| `B_A` | `sup_ℓ ‖Ã(ℓ)‖₁` |
| `B_A_lo` | та же величина, но округлённая ВНИЗ. Нужна потребителям, которые на `B_A` ДЕЛЯТ (`04-CODE/tube_offset.py`: `C_norm = Z1b/B_A_lo`, `BD_norm = Z1c/(1+B_A_lo)`): деление на завышенную `B_A` дало бы ЗАНИЖЕННУЮ, то есть не мажорантную `‖C‖` |
| `deltaP` | вариация центра по подбоксу (для липшицевой цепочки) |
| `tau_F` | масса σ-хвоста невязки (после исправлений §3.5) |
| `tail_sigma`, `tail_used` | σ-оценка хвоста и то, какая из двух оценок хвоста фактически взята (`interval-only` — σ-путь не использован) |
| `Z1b_sigma`, `Z1c_sigma` | σ-варианты `Z1b`, `Z1c`; в ворота идут интервальные |
| `engine`, `prec`, `time_s`, `wall_s`, `idx` | служебные: версия движка, точность arb, время счёта, тег бокса |
| `w2_sup`, `Ftail_sup`, `tail_interval` | хвост по `k`: `N_p < k ≤ N_ALG` и `k > N_ALG` |
| `dchk` | строгая верхняя граница расхождения σ-модели и движка по боксу: `‖ΔP‖·sup‖M′‖₁ + L·‖ΔP‖²`, где `‖ΔP‖` получена интервальной свёрткой погрешности перехода чебышёв→тейлор. Не выборка по точкам |
| `guard_lhs`, `guard_rhs`, `guard_ok`, `guard_in_gate` | охранный критерий `B_A·d_chk ≤ Y0/2` и признак того, что `d_chk` вошёл в ворота Ньютона–Канторовича |
| `lemma1_OK`, `lemma1_U_min`, `lemma1_margin_a`, `lemma1_margin_c` | лемма об области на этом боксе |
| `lemma1_nonzero_ok`, `lemma1_ReU_min_r_val`, `lemma1_ReU_min_R` | посылка ветви `W = U^ℓ`: минимум `Re U` на окружностях `\|t−c\| = r` и `\|t−c\| = 1.2`. Обе строго положительны, поэтому `U` не обращается в нуль в круге (гармоничность `Re U` плюс принцип минимума), и главная ветвь `U^ℓ` определена однозначно. Входит в `lemma1_OK` обязательным условием |

**Про имена полей `Re U`.** `lemma1_ReU_min_r_val` и `lemma1_ReU_min_R` — два
РАЗНЫХ поля (минимум на окружности `r` и на окружности `1.2` соответственно).
Ранее они назывались `lemma1_ReU_min_r`/`lemma1_ReU_min_R` и
различались только регистром последней буквы: `ConvertFrom-Json` в Windows
PowerShell 5.1 не различает ключи по регистру и отказывался читать такой файл
(«duplicated keys»). Нижний ключ переименован в `lemma1_ReU_min_r_val`, коллизии
больше нет — файл читается и PowerShell, и Python одинаково. Скрипты пакета
используют только `lemma1_ReU_min_R` (`tests/_numbers_check.py`), значения полей
при переименовании не пересчитывались.
| `bases_q`, `bases_q_s`, `bases_ok` | основания геометрических мажорант, обязаны быть `< 1` |
| `lemma_bases_K` | на сколько кусков резался бокс для этих двух проверок |
| `best.rho_prime`, `best.L`, `best.Zhat`, `best.gate_num`, `best.gate_den` | сработавший радиус ворот, липшицева константа, `Ẑ`, числитель `Y0 + B_A·d_chk` и знаменатель `1 − Ẑ` в `ρ* = num/den` |
| `best.L_mid` | та же липшицева `L`, но напечатанная к БЛИЖАЙШЕМУ (диагностика). В ворота идёт `best.L` — она округлена ВВЕРХ; сравнивать надо с ней |
| `best.rho_star_b` | радиус существования в **b-базисе**: `(Y0 + B_A·d_chk)/(1 − Ẑ)`. Поле `best.rho_star` — его синоним, оставлен для совместимости |
| `best.rho_star_X` | тот же радиус в норме `X`: `1.75·ρ*_b` (переход b-базис → `X` стоит множителя `sup‖b_k‖ ≤ 1.75`). **Сравнивать с шаром единственности теоремы A** (`1.75·10⁻⁷`) эту величину. В формулу `extra` (`tube_offset.py`, §4.5) подставляется НЕ она, а `rho_star_b` — множитель `1.75²` в формуле `extra` уже содержит перевод b→X, и подстановка `rho_star_X` дала бы лишний множитель `1.75³` |
| `containment` | есть ТОЛЬКО у якорного бокса (`ℓ₀ = 3`): `dX` — `‖P(3) − seed‖_X`, расхождение параметрического центра с замороженным сидом (вверх), `rho_X` — `1.75·ρ′` (вниз), `contains` — выполнено ли `dX + 1.75·10⁻²⁰ ≤ rho_X`. У остальных 45 боксов поле равно `null`, и это НЕ пропуск данных: сравнивать центр с сидом имеет смысл только там, где сид есть, а сид заморожен в единственной точке `ℓ = 3` |
| `passed` | итог бокса |

`glue.json` — сводная приёмка: ворота, охранный критерий, швы между
соседями, покрытие.

`offsets.json` — по каждому боксу существования: `ell0`, `w`, `lo`, `hi`

(несвежий протокол приёмки однажды уже оказался дефектом).

`03-CERTIFICATES/tube/_lane*.out`, `_lane*.log`, `_fin*.out` — протоколы
прогона трубки, и порядок здесь двухступенчатый. `_lane*.out` — первый

`04-CODE/tube_plan_span.txt` и `tube_plan_fix.txt`. Шесть `_lane*.log` —
служебные отметки старта полосы (одна строка); итог полосы пишется в
парный `_lane*.out`.

В `_lane*.out` есть **десять строк `FAIL R=nan ||D||=nan prod=nan`**, и
все десять — след первого прохода, а не расхождение:

* `t0000` падал на левом конце `lo = 1.9999999999999998` (на 1–2 ULP ниже
  `2.0`) до введения SPAN-CLIP (`04-CODE/tube_run.py`); он прошёл в
  `_fin0.out` с теми же числами, что стоят в `box_t0000.json`;
* остальные девять (`t0025`, `t0033`, `t0041`, `t0049`, `t0057`, `t0065`,
  `t0073`, `t0081`, `t0089`) выступали за свой бокс существования и были
  ЗАМЕНЕНЫ парами половинок — пометки «ЗАМЕНЁН» стоят прямо в
  `04-CODE/tube_plan.txt`. В пакете лежат половинки (`t0025L`/`t0025R` и
  так далее), а сертификатов с этими девятью тегами здесь нет и быть не
  должно.

Соответствие протокола сертификатам проверяемо и проверено: строк `BOX`
во всех девяти `.out` — 716, уникальных тегов 715, сертификатов 706;
сертификатов без строки в логе — 0; последняя по времени запись каждого
из 706 тегов совпадает со своим `box_t*.json` по `pass`, `R` и `prod` —
расхождений 0; тегов в логе без сертификата ровно девять, и это ровно те
девять заменённых.

Источник истины для одноимённых величин — файлы, перечисленные в `02-REPRODUCE.md` и читаемые шагами `verify_pkg.sh` (сам скрипт приёмки в пакет не входит — поставляется рецензенту отдельно, вместе с инструкцией).

переменная окружения или до-исправленная версия рядом):

* `_dchk_bound_test.py` — выведенная граница `d_chk` против прямого замера
  расхождения на сетке уплотняющихся точек: граница обязана оставаться выше
  замера при любом уплотнении (запас 2.9×);
* `_arc_cover_test.py` — дуговые коробки леммы об области обязаны накрывать
  окружность целиком, включая четыре точки, которые прежняя версия теряла;
* `_kappaG_bound.py` — константа переноса мажоранты `sup\|U−1\|` с центра
  `P(ℓ)` на решение `G*(ℓ)`: `κ_G ≤ 4.14` (нужна в §6.4.3);
* `_nozeros_check.py` — посылка (C.1) теоремы C: строгая интервальная
  сумма по 46 боксам, худший бокс `g06` даёт `0.3648 < 0.379`. Скрипт
  сначала проверяет себя на опубликованном `α(2)` и останавливается при
  расхождении.
* `_tail_bruteforce.py` — оценка хвоста столбца оператора против ПРЯМОГО
  счёта до степени `N_HI ≫ N_MAX`: граница берётся по интервалу бокса,
  замер — в точке внутри него по нижнему концу. Свидетельство, а не
  доказательство мажоранты (доказательство — вывод `tail_cols` в §4.6).
  Падает при `CLAIM_SCALE=0.001`;
* `_holo_radius.py` — нижняя оценка радиуса `R_G` области голоморфности
  `F` (§6.5): четыре посылки проверяются равномерно на шаре
  `B_X(P(ℓ), 1.75·10⁻⁷)`, откуда `R_G ≥ 1.75·10⁻⁷` против
  `ρ*_X ≤ 8.49·10⁻¹³`. Падает при `HOLO_RHO=0.05`.

Ещё два теста отвечают не на вопрос «верно ли посчитано», а на вопрос
«то ли посчитано»:

* `_classic_constants.py` — `δ` и `α` на концах отрезка против
  опубликованных значений Фейгенбаума (OEIS A006890/A006891, Briggs 1991).
  Единственная проверка пакета, внешняя по отношению к его собственному
  выводу `DF` (§3.9);
* `_layer_invariance.py` — спектр `DT` на 16 слоях `(c, r, N_p)` при
  четырёх `ℓ`: старшие собственные значения и счёт «снаружи ровно одно»
  от слоя не зависят. Численное свидетельство, не сертификат; строгое
  утверждение — теорема D (§10), сертификаты в `03-CERTIFICATES/layer/`.

## `03-CERTIFICATES/layer/` — сертификаты теоремы D (§10)

### Направление печати в `q_perturb_patch.json`

Соседний класс: арифметика строгая, а **печать** — нет. В файле

мажорант это неверная сторона, и два поля уходили ВНИЗ:
`sum_q16` `2.905946e-01` при шаре `0.29059461424251124…` и
`bound` `6.458110e-04` при `0.000645811022491365268…`. Наружу дефект не
вышел (статья публиковала свои числа вверх), но сравнение шло именно с
этими полями. Теперь `summary` — направленная печать верхних концов
шаров, о чём сказано в самом файле полем `summary.rounding`, а раздел J1
`_numbers_check.py` проверяет и направление, и тесноту, и тождества
между шарами (`sum_q16 = Q16_HAT + bound`, `inner_max = ‖Q̂‖₁ + E`,
`E = term_a + term_b`), и то, что `floats.*` — ближайшие double к шарам.

### Как пересчитать протоколы и сверить их с поставленными

`_holo_radius.py` и `_tau_share.py` пишут по `CERT_OUT`, а сторож I17/I18
читает то, что лежит в `03-CERTIFICATES/pointwise/`. Это разные пути
намеренно: прогон не должен переписывать поставленный сертификат. Чтобы
именно СВЕРИТЬ, задайте свой каталог и сравните файлы:

```
CERT_OUT=/путь/вне/пакета python 04-CODE/tests/_holo_radius.py
CERT_OUT=/путь/вне/пакета python 04-CODE/tests/_tau_share.py
diff <(python -m json.tool /путь/вне/пакета/holo_radius.json)      <(python -m json.tool 03-CERTIFICATES/pointwise/holo_radius.json)
```

`holo_radius.json` обязан совпасть с точностью до `wall`-полей (их там нет,
так что побайтно); `tau_share.json` — нет, и расхождение будет НЕ «на
проценты». Причин две, и обе двигают числа в одну сторону.

Первая — недетерминизм: `Y0` между прогонами гуляет на десятки процентов,
вместе с ним плывёт и `tau_break_factor`. Эта часть действительно невелика.

Вторая — крупнее. `tau_share.json` собран ДО поправки хвоста `Log α`
(метка `LOG-ARG-FIX` в `op_sig.py`, разбор в §3.5) и описывает те `τ`, на
которых построены ПОСТАВЛЕННЫЕ сертификаты. Поправка делает `τ` меньше,
поэтому свежий прогон текущим движком даёт доли `Z1_tau/Z1` меньше в 3.6–4.2
раза и множители запаса больше в 2.1–8.1 раза:

| бокс | доля: поставлено → свежий | множитель: поставлено → свежий |
|---|---|---|
| `g00` | 2.7060e-11 → 7.4976e-12 | 4.6206e+05 → 3.7295e+06 |
| `ganchor` | 9.5853e-14 → 2.3126e-14 | 1.3922e+08 → 9.6658e+08 |
| `g43` | 3.6784e-15 → 2.1030e-15 | 3.5812e+09 → 7.4788e+09 |

Числа §3.7 консервативны против ОБОИХ столбцов: доли опубликованы вверх и не
ниже большего из двух, множители — вниз и не выше меньшего из двух. Поэтому
поставленный файл не пересобран: он описывает поставленные сертификаты, а не
текущий движок, и подмена его свежим сделала бы таблицу §3.7 описанием не тех
`τ`, на которых сертификаты стоят.

Кроме этих трёх мест: все утверждения, на которых стоят
теоремы A, B и C, проверяются из пакета целиком, §3.8 же — сверка с
прежним подходом, ни на что не опирающаяся.
