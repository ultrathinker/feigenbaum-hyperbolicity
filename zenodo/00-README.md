# Существование и гиперболичность неподвижной точки ренормализации удвоения периода при нецелом показателе критической точки

Чистовой пакет. Здесь только математика: формулировки, доказательства,
код, которым они получены, и сертификаты, которые он выдал. Хроники
работы, промежуточных версий программ и переписки с проверяющими здесь нет.

## Что доказано

Пространство (базовый слой; про независимость от его выбора — §10):
аналитические функции в круге `D(c, r)`, `c = 3/5`, `r = 4/5`,
норма `‖h‖_X = Σ_k |h_k| r^k`; координата `t = |x|^ℓ`; касательное
подпространство `X₀ = {h : h(0) = 0}`; нормировке `G(0) = 1` отвечает не
`X₀`, а его аффинный сдвиг `𝒜 = 1 + X₀ = {G : G(0) = 1}` — именно там живёт
решение `G*(ℓ)` (подробности — `01-ARTICLE.md` §2).

**Теорема A (существование).** Для каждого `ℓ ∈ [2, 4]` уравнение
Фейгенбаума–Цвитановича имеет решение `G*(ℓ) ∈ 𝒜` в шаре радиуса
`ρ*_b(ℓ) ≤ 4.85·10⁻¹³` (в `X`-норме `ρ*_X = 1.75ρ*_b ≤ 8.49·10⁻¹³`) вокруг явно построенного параметризованного центра
`P(ℓ)`; это решение единственно в аффинном шаре `P(ℓ) + B_{X₀}(0, 1.75·10⁻⁷) ⊂ 𝒜`,
то есть на срезе нормировки `𝒜`, а не во всём `X` (подробности — `01-ARTICLE.md` §2). 46 боксов, ворота
Ньютона–Канторовича, объединение накрывает `[2.0000, 4.0075]`.

**Теорема B (гиперболичность).** Для каждого `ℓ ∈ [2, 4]` производная
`DT(G*(ℓ))|_{X₀}` имеет **ровно одно** собственное значение вне единичного
круга; остальной спектр строго внутри. Отсюда: неустойчивое направление
одномерно, `δ(ℓ)` вещественно и просто. 706 боксов, теорема Руше на
единичной окружности, худшее значение полного теста приёмки `0.9919 < 1`, объединение
накрывает `[2.0000, 4.0012]`.

**Теорема C (аналитичность по ℓ).** Отображения `ℓ ↦ G*(ℓ) ∈ 𝒜` (`𝒜 = 1+X₀` — аффинный срез нормировки `G(0)=1`, см. `01-ARTICLE.md` §2) и
`ℓ ↦ δ(ℓ)` вещественно-аналитичны на `[2, 4]`. Доказательство — §6:
комплексификация `X`, аналитическая теорема о неявной функции на
сертифицированном шаре, риссов проектор по единичной окружности (где
резольвента ограничена строго) для простого собственного значения.
Все константы выписаны, недоказанных посылок не осталось.

**Теорема D (независимость от слоя).** Для любого слоя `(c′, r′)` из явно
предъявленного и сертифицированного семейства `𝔉` ненулевой спектр
`DT(G*(ℓ))` на `X₀(c′, r′)` совпадает со спектром на базовом слое
`X₀(3/5, 4/5)` вместе с алгебраическими кратностями; в частности, счёт
«снаружи ровно одно» и само `δ(ℓ)` от выбора слоя не зависят.
Доказательство — §10: продолжение `G*` и собственных функций по самому
уравнению, компактность через спектральный радиус в алгебре Винера,
совпадение корневых подпространств. `𝔉` предъявлено как прямоугольник
`𝔔 = (0.56, 0.64) × (0.76, 0.84)`, 14 отдельных слоёв по
`[0.55, 0.70] × [0.70, 0.90]` и связный коридор из 7 ячеек между ними
(перенос сертификатов `P→G*` §10.7 сертифицирован при `c+r ≤ 1.53` —
этот домен содержит всё предъявленное семейство целиком: его самая
широкая точка — ячейка коридора при `c+r = 1.522`, см. §10.13);
что `𝔉` можно расширить до ЛЮБОГО `(c, r)`,
не доказано (§10.9).

Теоремы A и B **равномерны по ℓ**: для каждого бокса проверяется
неравенство, верное сразу для всех `ℓ` этого бокса, а боксы перекрываются.
Это не счёт в конечном наборе точек и не аргумент «по непрерывности».

Счёт «снаружи ровно одно», который цепочка боксов только переносит,
получен внутри работы двумя независимыми путями: инерционным счётом
относительно единичной окружности (§4.7, интервальная инерция) и
спектральной дефляцией с проверкой собственной пары по Кравчику (§5.2).
Независимость — по счёту спектра; оба метода применены к ОДНОЙ сборке
матрицы `DT`, которая перекрёстно проверена отдельным путём (§3.9).
Предъявлены они по-разному, и это стоит знать заранее: у дефляции есть
json-сертификаты в `03-CERTIFICATES/pointwise/`, а у якоря — протокол
`03-CERTIFICATES/anchor-inertia/REPORT-ANCHOR.md` и скрипты, которые надо
запустить (`s3_prepare_AB.py` — интервальный LDL, `_anchor_check.py` —
независимый пересчёт вердикта); оба с круга 5 завершаются ненулевым кодом
при расхождении, промежуточный `_s3s4_result.json` в пакет не входит.

## Как это проверять

Работа компьютерная, поэтому её нельзя проверить чтением одной прозы:
доказательство состоит из неравенств, которые проверяет код, и чисел,
которые он выдал. Минимальный маршрут проверяющего:

0. `python _manifest.py verify` — пакет цел и совпадает с манифестом:
   ни изменённых, ни пропавших, ни лишних файлов. Ненулевой код возврата
   означает расхождение. (Запуск **без** `verify` не проверяет ничего — он
   ПЕРЕЗАПИСЫВАЕТ манифест под то, что лежит на диске.)
   Верификатор не может удостоверить сам себя — `_manifest.py` входит в
   манифест, но подделанный верификатор может и промолчать. Поэтому сверьте
   хотя бы раз **внешним инструментом**, не кодом пакета:
   `sha256sum -c --quiet MANIFEST.sha256` (Linux/macOS/Git Bash; формат
   манифеста стандартный). Тишина и код возврата 0 = все 958 файлов, включая
   `_manifest.py`, совпали. На чистой Windows без Git Bash —
   PowerShell-эквивалент: `Get-Content MANIFEST.sha256 | Where-Object {$_ -notmatch '^#'} | ForEach-Object {$h,$f=$_ -split '  ',2; if ((Get-FileHash $f -Algorithm SHA256).Hash.ToLower() -ne $h) {"MISMATCH: $f"}}` — пустой вывод = совпадение. Вне манифеста — сам `MANIFEST.sha256` и
   каталоги `__pycache__` (побочный продукт запуска Python; на доказательство
   не влияют и могут быть удалены перед проверкой). В рабочем дереве автора
   вне манифеста лежит ещё статус-файл с хроникой процесса; он не звено
   доказательства и в поставляемую копию не входит — если рядом с
   манифестом его нет, так и должно быть. Учтите: `sha256sum -c`
   проверяет только перечисленные в манифесте файлы и по построению НЕ
   сообщает о лишних файлах, которых в манифесте нет.
1. `04-CODE/tests/_classic_constants.py` — самое короткое, с чего стоит
   начать: движок считает `δ` и `α` на концах отрезка и сверяет их с
   опубликованными значениями Фейгенбаума (15 знаков при `ℓ = 2`).
   Это одна из двух проверок пакета, внешних по отношению к его
   собственному выводу производной; вторая — `control_check()` в
   `04-CODE/tests/_nozeros_check.py`, где `α` при `ℓ = 2`, посчитанная
   из ветки `branch_g00.npz`, сверяется с опубликованным значением
   (OEIS A006891) на 14 знаков, и расхождение валит тест.
2. `04-CODE/tests/_tau_test.py` — мажоранты хвостов действительно мажоранты
   (тест устроен так, что старая версия обязана падать; если не падает —
   сломан сам тест).
3. `cert.py` на одном-двух боксах — сверить с `03-CERTIFICATES/existence/`.
   Аргументы обязательны: `python cert.py g00 2.025 0.05 6 8` (тег, центр,
   ширина, m, D — поля `idx`, `ell0`, `w`, `m`, `D` соответствующего
   `box_g*.json`). БЕЗ последних двух `cert.py` берёт свои умолчания
   `m=8, D=8` — они НЕ совпадают с параметрами многих шипованных боксов
   (у `g00`, например, `m=6`), и сверка получится с другими числами.
4. `tube_run.py` на одной полосе плана — сверить с `03-CERTIFICATES/tube/`.
   Аргумент — не бокс, а ПОЛОСА: `python tube_run.py <полоса> <всего-полос>
   [файл-плана]`, план по умолчанию — `04-CODE/tube_plan.txt`. Чтобы
   посчитать ровно один бокс, положите его строку плана в свой файл и
   запустите `python tube_run.py 0 1 <свой-план>`.

   Пункты 3–4 **пишут** файлы. По умолчанию они пишут во временный каталог
   ОС, и пакет остаётся нетронутым; чтобы положить результат в свой каталог,
   задайте `CERT_OUT` / `HYP_TUBE_OUT` абсолютным путём (`02-REPRODUCE.md`).
5. `tube_accept.py` — приёмка целиком.
6. `03-CERTIFICATES/anchor-inertia/_anchor_check.py` — якорь, float-сверка;
   строгая интервальная часть — `s3_prepare_AB.py` + `s5s6_robustness.py`
   там же (подробности — `02-REPRODUCE.md` §7).
7. `04-CODE/tests/_layer_invariance.py` — зависит ли спектр от выбора
   слоя `(c, r)`: численная иллюстрация на 16 слоях.
8. `04-CODE/layer/` — строгая часть того же вопроса (теорема D):
   `layer_mutation1.py` и `layer_mutation2.py` — самое короткое, показывают,
   что гейты сертификатора действительно способны провалиться;
   `layer_recheck_all.py` — все 644 точечных сертификата (десятки минут);
   `layer_cells_bisect.py` — континуальная ячейка `𝔔` и её граница.
   Протоколы, с которыми сверяться, — в `03-CERTIFICATES/layer/`.

Подробности и ожидаемые числа — в `02-REPRODUCE.md`.

## Один вопрос, который стоит задавать всему

Работа устроена как цепочка мажорант. Все ошибки, которые в ней
находились, были одного рода: **ограничивалась не сама величина, а её
модель** — усечённый ряд вместо функции, максимум по выборке вместо
супремума, хвост усечения вместо хвоста композиции. Разбор таких мест —
§3.3, §3.5, §4.6, §4.9.

Полезно знать и обратное: ворота вида «цепочка неравенств `< 1`» ловят
**завышение** оценки и не ловят **занижение** (проверено внесением
намеренных дефектов, §4.10). Поэтому строгость каждой величины держится на
её выводе, а не на том, что сертификат прошёл.
