# Как воспроизвести

Окружение. Сертификаты пакета посчитаны ровно на этой сборке — она и есть
опорная, потому что результат зависит от арифметического бэкенда:

```
python        3.13.13
python-flint  0.9.0   (FLINT 3.6.0)
numpy         2.5.0
scipy         1.18.0
mpmath        1.3.0
Windows-11-10.0.26200-SP0, 24 логических ядра
```

Нижняя граница совместимости — Python 3.12 и `python-flint` 0.9.0 (3.12 —
потому что заявленные выше `numpy 2.5.0` и `scipy 1.18.0` объявляют
`Requires-Python >=3.12`; сам `python-flint` 0.9.0 пошёл бы и с 3.10); более
старый `python-flint` не годится (в 0.8 нет части использованных методов
`arb`). На другой минорной версии FLINT числа обязаны совпасть с точностью
до включения интервалов, а не побитово: расхождение в последнем бите
мажоранты допустимо, СМЕНА ВЕРДИКТА — нет. Если вердикт сменился,
это баг сборки или дефект пакета, и его надо разбирать, а не списывать
на «другую машину».
Всё считалось на одной машине (24 логических ядра), параллельно пятью
полосами; общая стоимость — около 8.9 ядро-часов (0.70 на существование — сумма time_s по 46 box_g*.json; 8.20 на трубку — сумма wall_s по 706 box_t*.json).

Все команды запускаются из `04-CODE/`. Каталоги задаются переменными
окружения — проще всего выставить их один раз:

```
export PKG=/путь/к/этому/пакету   # каталог, в котором лежит 00-README.md
export HYP_ENG="$PKG/04-CODE"
export HYP_BRANCHES="$PKG/03-CERTIFICATES/branches"
export HYP_CERTS="$PKG/03-CERTIFICATES/existence"
export HYP_TUBE_OUT="$PKG/03-CERTIFICATES/tube"
export HYP_OFFSETS="$PKG/03-CERTIFICATES/tube/offsets.json"
export CERT_OUT=/путь/вне/пакета/out        # КУДА писать; внутрь пакета —
export GLUE_OUT="$CERT_OUT"                 # только при осознанной пересборке
export PYTHONIOENCODING=utf-8
```

⚠ **Внимание: `HYP_TUBE_OUT` и `HYP_OFFSETS` — не только читательские.**
В блоке выше они выставлены НА КАТАЛОГ ПАКЕТА сознательно — чтобы проверки
(`tube_accept.py`, `_containment.py`, `tests/_stats.py`) сверяли именно сертификаты
пакета. Но `tube_run.py` ПИШЕТ боксы в `$HYP_TUBE_OUT` (`tube_run.py:44-46, 94`), а
`tube_offset.py` — `offsets.json` в `$HYP_OFFSETS`. Значит, перед шагами пересчёта
трубки (§3 и §4 ниже) обе переменные НАДО перенацелить вне пакета:

```
export HYP_TUBE_OUT=/путь/вне/пакета/tube-out
export HYP_OFFSETS=/путь/вне/пакета/tube-out/offsets.json
```

Иначе буквальное следование инструкции перезапишет сертификаты пакета
свежим прогоном, и сверка перестанет быть сверкой (проверка манифеста
поймает это, но только постфактум).

Тесты лежат в `04-CODE/tests/`. Готовые ветки `branch_*.npz` есть в
`03-CERTIFICATES/branches/`; их можно и построить заново (п. 1).

**Проверено:** с этими переменными пакет считает у себя же — `glue.py`
даёт 46/46 и покрытие `[2.0000, 4.0075]`; `tube_accept.py` —
`ПРИЁМКА: ПРОЙДЕНА`, 706 боксов, худший полный тест `≤ 0.9919`
(точное значение `0.991843707457`, статья округляет вверх);
`tests/_tau_test.py` — 15 провалов у до-исправленной версии и 0 у текущей;
`tests/_numbers_check.py` — ноль расхождений между статьёй и сертификатами;
`tests/_classic_constants.py` — совпадение с классическими δ и α на 15/14
знаков при `ℓ = 2`.

Про `Y0` и `Z1` отдельного «ожидаемого» числа нет намеренно: см. замечание
о воспроизводимости в конце файла — `Y0` гуляет между прогонами на десятки
процентов, и сверять надо прохождение ворот, а не значение.

По умолчанию оба шаговых скрипта (`runplan6.sh`, `rerun_all.sh`) вызывают

## 3. Трубка гиперболичности

```
python tube_run.py <полоса> 5 tube_plan.txt        # полосы 0..4 параллельно
python tube_run.py 0 1 tube_plan_fix.txt           # мостовой бокс на стыке ширин
python tube_run.py <полоса> 5 tube_plan_span.txt   # 18 боксов взамен девяти
```

Девять боксов исходного плана (`t0025, t0033, t0041, t0049, t0057, t0065,
t0073, t0081, t0089`) заменены восемнадцатью из `tube_plan_span.txt`: они
выступали за свой бокс существования, где член `extra` не обоснован. В
пакете лежат только действующие 706.

До круга 6 эти девять строк оставались в `tube_plan.txt` живыми, и
буквальный прогон по команде выше пересчитывал их заново — получалось 715
файлов, из них девять лишних, и манифест переставал сходиться. Теперь они
в плане закомментированы (`tube_run.py` пропускает строки с `#`), так что
687 + 18 + 1 = 706 выходит само собой.

Итого 706 боксов, 8.20 ядро-часа (сумма `wall_s`; та же цифра в §4.8 статьи). Каждый бокс: строгая резольвента `R`
(`N` узлов на единичной окружности + дуговая оценка) и строгое `‖Δ‖` по
боксу с подразбиением `K = 4`.

## 4. Смещение неподвижной точки и связь с хвостом

```

```

По каждому боксу существования считает строгий `‖M′‖₁` по боксу и
складывает `extra` (смещение `P → G*`) и границы блоков `B`, `C`, `D`.
Пишет `offsets.json`. Ожидаемое: `extra ≤ 2.86·10⁻⁶`,
`‖C‖ ≤ 4.07·10⁻⁴`, `‖[B;D]‖ ≤ 1.95·10⁻⁴` (`extra` наследует межсборочный разброс

другой сборке — вывод §4.8 от этого не меняется, запас в 6-м знаке).

`_tau_share.py` пишет `tau_share.json`, который читает `_numbers_check.py`, а
`_z1bc_sub.py` воспроизводит таблицу §3.2.

```
python tests/_tau_share.py
python tests/_z1bc_sub.py
```

`_arb_sanity_battery.py` — санитарная батарея по API `python-flint`. Весь
пакет держится на строгой интервальной арифметике; если в ЭТОЙ сборке
направление округления, семантика сравнения шаров или конверсия `float(arb)`
ведут себя не так, как предполагает `04-CODE`, подорваны все сертификаты
сразу, а не одно утверждение. Эталон — точная рациональная арифметика, а не
flint сам с собой. Ожидаемое: `санитарная батарея arb: ok`.

`_dchk_check.py` — что на самом деле меряет встроенная самопроверка `dchk`
(была версия с ошибкой на единицу в степени `R`). Ожидаемое:
`DCHK-СВЕРКА: ok (охранный критерий консервативен)`.

`_kmode.py` — где сидит `λ_K = 7.16329` (§5.1.2) и не спорит ли оно с
теоремой B; отождествление `K` с правым собственным вектором не
сертифицировано и названо гипотезой (§9). Ожидаемое: `K-МОДА: ok`.

`_reu_min_l25.py` — строгая нижняя граница `min Re U` и `min |U|` при
ℓ = 5/2, на которой стоит однозначность ветви Миллера (§5.3.2). До
23.08.2026 у этого числа не было носителя в пакете. Ожидаемое:
`сертификат не обещает больше, чем посчитано заново`.

`_scan_vs_tube.py` — сверка ДВУХ независимых счётов `δ(ℓ)` и `λ₂(ℓ)`: скана
по 101 точке (`05-DATA/delta_scan.json`) и центров 697 боксов трубки. Разные
коды и разные пути к матрице; совпадение — независимое подтверждение обоих.
Ожидаемое: `СКАН vs ТРУБКА: ok`.

`_tau_share.py` — какая доля `Y0` и `Z1` ещё держится на τ-бухгалтерии
`sig_lib`, дефект которой известен (занижение в 2.7–4.4 раза). Пишет протокол
`tau_share.json`.

`_xresid_tail_F_l25.py` — строгая верхняя граница `tail_F / F_norm_strict`
при ℓ = 5/2; этой проверкой было поймано, что цитируемое «строгое» число
совпадало с УСТАРЕВШЕЙ константой другой ветви. Ожидаемое:
`сертификат не обещает меньше, чем честно пересчитано`.

`_z1bc_sub.py` — снятие миллеровской обёртки в `Z1b`/`Z1c` подразбиением
бокса: супремум по боксу равен максимуму супремумов по кускам, поэтому
разрезание сокращает раздувание `e^{O(w·N_W)}`. Печатает таблицу выигрыша
по `K`.

`_containment.py` — каждый бокс трубки лежит внутри своего бокса
существования (706 из 706; у `t0000` запас нулевой по построению, он
выступает за `[2,4]` слева на 2.2·10⁻¹⁶).

`_anchor_check.py` — якорная инерция: 80 пивотов LDLᵀ, знаки (79, 1, 0).
Ожидаемое: `ПРОВЕРКА ЯКОРЯ: ok`.

`_dchk_bound_test.py` — выведенная граница `d_chk` против прямого замера
расхождения σ-модели и движка на уплотняющейся сетке. Смысл теста в том,
что граница обязана оставаться выше замера **при любом уплотнении**:
прежняя версия брала максимум по фиксированному набору точек и занижала
величину в 1.39 раза. Ожидаемое: граница выше замера, запас ≈ 2.9×.

`_arc_cover_test.py` — дуговые коробки леммы об области обязаны накрывать
окружность целиком. Прежняя версия вычисляла `cos/sin` в серединах дуг и
теряла четыре точки; тест на ней падает. Ожидаемое: ни одной строки
`*** FAIL`, последняя строка — `проверок в ветке m=0: 2`. Счётчика
«непокрытых точек» скрипт не печатает: покрытие проверяется по каждой из
четырёх точек (`θ = 0, π/2, π, 3π/2`) отдельно, статусом ДА/НЕТ на старую и
новую коробку.

`_kappaG_bound.py` — константа переноса мажоранты `sup|U−1|` с центра
`P(ℓ)` на решение `G*(ℓ)`, нужная в §6.4.3. Супремум по боксу берётся
интервально, с подразбиением на восемь частей; коэффициенты перед этим
переразлагаются в центр `c` — норма `X` определена именно через них.
Множитель `α_G^{−ℓ−1}/|G(1)|²` берётся точно, как `|G(1)|^{ℓ−1}` (это одна
и та же величина, см. §6.4.3 и §10.7). Ожидаемое: `κ_G ≤ 4.14` (фактически
`4.130319`, бокс `g43`), `min|G(1)| ≈ 0.3987`, запас против требуемого —
почти шесть порядков. Контроль согласия с §10.7: запуск с аргументом `1`
(`python tests/_kappaG_bound.py 1`, то же грубое подразбиение) даёт
`4.415912` на `g43` против `4.4197` в §10.7.

`_nozeros_check.py` — посылка (C.1) теоремы C: строгая интервальная сумма
`Σ|a_k(ℓ)|·α(ℓ)^{−kℓ}·(c+r)^k` по всем 46 боксам. Перед счётом скрипт
проверяет себя на контрольном значении `α(2) = 2.5029078750959` и
останавливается, если оно не воспроизводится. Ожидаемое: худший бокс
`g06`, `0.3648 < 0.379`, и `min|G(1)| ≈ 0.3963 > 0.393`. Тем же кодом
делается второй проход на широком домене `c+r = 1.53` — он нужен §10.7,
где мажоранта `sup|U|` применяется на слоях шире базового круга;
ожидаемое: тот же худший бокс `g06`, `0.399346 < 0.400`.

`_tail_bruteforce.py` — оценка хвоста столбца оператора (`tail_cols`)
против ПРЯМОГО счёта. Столбец `res` строится заново до степени
`N_HI` (по умолчанию 600, аргументом можно задать больше) — то есть далеко
за `N_MAX = 320`, до которого его считает движок, — и измеренная масса
хвоста сравнивается с границей. Тонкость, без которой тест бесполезен:
граница берётся по ИНТЕРВАЛУ бокса, а замер делается в ТОЧКЕ внутри него.
На интервале коэффициенты `res` — широкие шары (зависимостное раздутие по
`ℓ`); сравнение верхних концов границы и замера расходится на ширину шаров
и даёт мнимое нарушение. Поэтому замеренная масса хвоста складывается из
НИЖНИХ концов `|res_j|` (`abs(ball_j).lower()`) — это честная (заниженная)
нижняя оценка истинной измеренной величины, а не нижняя грань нормы
столбца: тест лишь становится от этого строже, поскольку сравнивает
границу с занижением, а не с завышением измеренного. Проверяемое
утверждение: граница по боксу мажорирует замер в любой точке этого бокса. Ожидаемое: измеренное ниже
границы, худшее отношение около 0.04. Тест умеет провалиться — запустите
его с `CLAIM_SCALE=0.001` (граница искусственно ужимается в тысячу раз),
он обязан напечатать ПРОВАЛ.

Чего этот тест НЕ делает: он замеряет несколько столбцов в отдельных
точках, поэтому его прохождение — свидетельство, а не доказательство
мажоранты. Доказательством остаётся вывод `tail_cols` в `tube_lib.py`
(§4.6); тест ловит ошибку в этом выводе, но не заменяет его.

`_holo_radius.py` — нижняя оценка радиуса `R_G` области голоморфности `F`
(§6.5), без которой применение аналитической ТНФ в точке `G*(ℓ₀)` повисает
в воздухе: теорема требует голоморфности в окрестности `G*`, а не в
окрестности центра `P`. Тест проверяет все четыре посылки §6.5 не в центре,
а равномерно на шаре `B_X(P(ℓ), 1.75·10⁻⁷)` — том самом шаре
единственности теоремы A: отделённость `|G(1)|` от нуля, `|arg α_G| < π/2`
(отсюда `Re α_G > 0` и однозначность логарифма), вложенность образа `s_G` в
`D(c,r)` против сертифицированного `margin_a`, и `q̂ < 1` (отсюда и
сходимость ряда композиции, и `W_G(D) ⋐ D`). Ожидаемое: 46/46,
`q̂ ≤ 0.955131`, вывод `R_G ≥ 1.75·10⁻⁷` против `ρ*_X ≤ 8.49·10⁻¹³` — запас
`2.06·10⁵`. Тест умеет провалиться: `HOLO_RHO=0.05` задаёт заведомо
слишком большой шар, и посылки обязаны сломаться. Чего он не делает:
`q̂` и `ΔU` берутся из той же `tube_lib._compute_L`, что стоит в воротах
сертификата, поэтому тест проверяет выполнение посылок, а не правильность
формулы, которой они посчитаны.

## 5б. Две внешние проверки и перекрёстная сборка DT

```
python tests/_classic_constants.py
python tests/_layer_invariance.py
python tests/_dt_fd_cross.py
python tests/_crosscheck.py
```

`_classic_constants.py` считает `δ` и `α` при `ℓ = 2` и `ℓ = 4`
степенным методом в arb по матрице `DT` и сверяет с опубликованными
значениями. Ожидаемое: при `ℓ = 2` совпадение `δ` на 15 знаков, `α` на 14;
при `ℓ = 4` — на все 11 опубликованных. Время ~5 мин.

`_layer_invariance.py` пересчитывает спектр на 16 слоях `(c, r, N_p)`
при четырёх значениях `ℓ`. Ожидаемое: двадцать старших собственных
значений совпадают с базовым слоем на `10⁻¹⁴`, счёт «снаружи ровно одно»
везде один и тот же. Время ~15 мин. Это численная иллюстрация; строгое
утверждение о независимости от слоя — теорема D (§10), её сертификаты
пересчитываются кодом `04-CODE/layer/` (см. §5в ниже).

`_crosscheck.py` — независимая перекрёстная проверка трубки: для
выборки боксов (по умолчанию 6) считает `‖Δ‖` и `R` ВТОРЫМ, float/numpy
путём (без arb) и сравнивает с записанными в сертификате строгими
значениями — они обязаны быть НЕ МЕНЬШЕ выборочных. При пустой выборке
боксов тест явно падает, а не проходит (докстринг файла). Умеет
проваливаться: тот же прогон дополнительно проверяет намеренно
испорченную величину (`R`, делённое на 3) — она обязана быть пойманной.
Аргументы (необязательные): число боксов, точек по ℓ, точек по кругу
(по умолчанию `6, 21, 720`).

`_dt_fd_cross.py` собирает матрицу `DT` при `ℓ = 3` ВТОРЫМ путём: столбцы
получаются центральной конечной разностью ЗНАЧЕНИЯ оператора (`tube_lib.compute_F_poly`),
без единого обращения к ручной аналитической производной `DF_at_ell` и к `M_full`,
и сверяет обе сборки поэлементно и по спектру (§3.9). Ожидаемое: относительное
расхождение `1.18·10⁻¹²` (порог `10⁻⁶`), `δ = 6.084689074262` в обоих путях,
«снаружи ровно одно» в обоих. Время ~92 с. Скрипт ничего в пакет не пишет:
отчёт и лог идут в `CERT_OUT` (или во временную папку), путь к отчёту
переопределяется `DT_FD_REPORT`. Аргументы (необязательные): `ℓ₀`, полушаг `eps`,
число столбцов (по умолчанию `3.0`, `1e-12`, все 80). Проверены также точки
`2.5` (расхождение `7.36·10⁻¹⁴`) и `3.9` (`1.12·10⁻¹²`) — таблица в §3.9.

## 5в. Теорема D: независимость от слоя (§10)

Код — `04-CODE/layer/`, протоколы — `03-CERTIFICATES/layer/`. Все скрипты
запускаются прямо из корня пакета, без переменных окружения: пути к движку
(`HYP_ENG`) и веткам (`HYP_BRANCHES`) вычисляются относительно самого файла.

Скрипты, которые **пишут** артефакты (`cert.py`, `rig2fix3.py`,
`tube_run.py`, `glue.py`, `04-CODE/layer/*`, `tests/pure_interval.py`), по
умолчанию пишут **мимо пакета** — во временный каталог ОС
(`%TEMP%/renorm_out`, `%TEMP%/layer_out` и т.п.). Так сделано намеренно:
иначе запуск «как есть» дописывал бы файлы внутрь пакета и ломал сверку с
`MANIFEST.sha256` — именно так и случалось при внешних проверках, где
двое независимо получили «лишние файлы». Чтобы пересобрать артефакты
самого пакета, каталог назначается явно и **абсолютным путём**
(относительный берётся от текущего каталога, а не от корня пакета).

## Замечание о воспроизводимости

Несколько мест устроены **адаптивно**: подразбиение бокса удваивается,
пока величина не сядет (`_tails_subdivided`, `_z1bc_subdivided`, проверка
леммы и оснований). Критерий остановки сравнивает float-значения, поэтому
на другой машине или другой сборке `python-flint` число кусков `K` может
отличаться — и, соответственно, отличаться в последних знаках хвостовые
подкомпоненты (`w2_sup`, `Ftail_sup`). Это не расхождение результатов:
**любое `K` даёт верную верхнюю границу**, супремум по боксу равен
максимуму супремумов по кускам при любом разбиении. Проверять надо не
побитовое совпадение, а выполнение ворот и приёмки.

Ровно такое расхождение наблюдалось при независимом пересчёте на другой
машине: `K = 2` против `K = 4` в пакете, `w2_sup` отличается в сто раз при
абсолютной величине 10⁻⁵³ — то есть на сорок порядков ниже `Y0` (`Y0 ∈ [6.24·10⁻¹⁴, 4.31·10⁻¹³]` по 46 боксам). Все
несущие числа (`Y0`, `Z1`, `Ẑ`, `L`, `ρ*`) совпали точно.

**От чего зависит сертификат трубки.** `tube_run.py` строит
`DT = hyp_rouche.dt_from_pkg(pkg)`, а тот читает из пакета бокса только
`pkg['M_full']` — головные коэффициенты матрицы. Оценка хвоста столбца
(`pkg['tail_cols']`) в `DT` не входит: она нужна `compute_Z1` для `Z1b/Z1c`,
то есть сертификату СУЩЕСТВОВАНИЯ и через него смещениям `extra` и нормам
блоков `‖C‖`, `‖[B;D]‖`. Это стоит знать, если пересчитывать пакет по
частям: правка хвостовой оценки требует заново считать 46 боксов
существования, смещения и приёмку, но не 706 боксов трубки. Проверять это
предположение надо не рассуждением, а пересчётом нескольких боксов трубки и
побитовой сверкой json (в пакете так и сделано на `t0215`, `t0464`, `t0695`).

**Что покрывает `tests/_numbers_check.py`.** Двенадцать поименованных
разделов вывода — `A`, `F`, `F2`, `G`, `B`, `C`, `D`, `E`, `E2`, `H`, `I`, `J`
(порядок печати именно такой). Ядро — A–E: числа
существования, склейки и трубки против сертификатов; §6 (`L`, `ρ*`,
возмущение, `κ_G` — живым запуском `tests/_kappaG_bound.py`); §5.2.1
(`‖Q★¹⁶‖₁` и тождество для `ρ(Q★)`); посылку (C.1) — живым запуском
`tests/_nozeros_check.py` со сверкой худшего бокса и его значения против
ВСЕХ упоминаний в статье. Остальные разделы: `F` и `F2` — направление
округления во всех документах пакета и числа якорного бокса; `G` — ссылки
документов на файлы пакета; `H` — словарь парных обозначений; `I` — весь §10
(теорема D, подпункты I1–I19); `J` — величины, публиковавшиеся без носителя
или без направления округления. Последняя проверка появилась потому, что два
места статьи расходились между собой (`0.3782` на `g04` против `0.3648` на
`g06`), и тест этого не замечал. Проверять тест на фальсификацию просто:
подставьте в статью другое число — сверка обязана упасть.

### Ещё две вещи, которые стоит знать при пересчёте

**`Y0` может отличаться на десятки процентов между прогонами — это не
противоречит требованию из §1 о побайтном совпадении `branch_g01.npz`.**
Побайтная гарантия §1 — про сид и продолжение по ℓ, зафиксированные в
`hiprec_seeds.json`; `Y0` считается из ОТДЕЛЬНОГО промежуточного центра
`c_a`. Сид неподвижной точки строится `solve_fixed_point` во float, и его
последние биты не детерминированы (порядок суммирования, BLAS). Разница
`c_a` порядка 10⁻¹⁵ усиливается σ-оператором и даёт `Y0` то 3.4·10⁻¹³, то
4.6·10⁻¹³ на одном и том же боксе `g01` (замерено на повторных прогонах).
На вердикт это не влияет: ворота требуют `Y0 ≤ 9.2·10⁻⁸`, то есть при
наблюдаемых `Y0 ~ 4·10⁻¹³` запас составляет `2.3·10⁵` раз — пять с
половиной порядков, а не восемь, как здесь стояло до круга 6. Сверять надо прохождение ворот, а не совпадение `Y0`.

Тот же сид даёт разброс и в `extra`/`rho_star_b` (`tube_offset.py`), и в `τ_F`
(бокс `gtop`). `rho_star_b = (Y0 + B_A·dchk)/(1−Ẑ)` (`rig2fix3.py:780`) напрямую
включает `Y0`, а `dchk` (метка DCHK-CONV в `rig2fix3.py`) строится из того
же float-сида через `‖ΔP‖`; `extra` (`tube_offset.py`) линеен по `rho_star_b`. На
независимой регенерации (другая сборка flint/gmp/mpfr, свой LAPACK/BLAS) для
бокса `gtop`: `rho_star_b` `3.404·10⁻¹³ → 3.531·10⁻¹³` (+3.7%), `extra`
`2.852·10⁻⁶ → 2.958·10⁻⁶` (+3.7%), `τ_F` `3.980·10⁻¹⁹ → 5.603·10⁻¹⁹` (+41%,
`gtop` — вырожденный бокс, `τ_F` там на порядок меньше соседних боксов, поэтому
относительный разброс больше). Все три остаются на 4-5 порядков меньше того, что
реально ограничивает вывод (`‖Δ‖ ≈ 0.13…0.28` для `extra`; ворота `Y0 ≤ 9.2·10⁻⁸`
для `τ_F`), и на пересчитанном неравенстве §4.8 с бо́льшим `extra` запас меняется
в 6-м знаке. Сверять надо прохождение ворот и приёмки, а не побитовое совпадение
этих величин.

**Чего тест `_tau_test.py` не покрывает.** Он проверяет мажоранты при
нулевом входном `τ` (то есть само усечение). Снос ненулевого `τ_M` через
`t_exp_seed` (`‖X₀‖e^{R}(e^{2τ_M}−1)`) проверен только аналитически —
двумя независимыми выводами, но не тестом.
Это единственное место в цепочке правок, где нет фальсифицирующего теста.
